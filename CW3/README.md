# CW3: пайплайн предобработки данных

## Цель работы

Собрать единый пайплайн предобработки для датасета Titanic и проверить, что преобразования не создают утечку данных из test в train.

## Классификация признаков

### Числовые признаки

Используются:

- `Age` — возраст;
- `Fare` — стоимость билета;
- `SibSp` — количество братьев, сестер или супругов на борту;
- `Parch` — количество родителей или детей на борту;
- `FamilySize` — новый признак: `SibSp + Parch + 1`.

### Категориальные признаки

Используются:

- `Pclass` — класс билета;
- `Sex` — пол;
- `Embarked` — порт посадки;
- `CabinDeck` — первая буква номера каюты.

Из `Cabin` извлекается `CabinDeck`. Если каюта не указана, создаётся значение `Unknown`.

### Исключённые признаки

- `PassengerId` — технический идентификатор, не несущий устойчивого признака пассажира;
- `Name` — текстовый признак с высокой кардинальностью; при необходимости из него можно отдельно извлечь обращение (`Mr`, `Mrs`, `Miss`);
- `Ticket` — строковый номер с высокой кардинальностью; его нельзя напрямую one-hot кодировать без дополнительного проектирования признаков;
- исходный `Cabin` — заменён на более компактный признак `CabinDeck`.

## Стратегии обработки

### Числовые признаки

Для `Age` используется медиана. В датасете есть пропуски, а распределение возраста не идеально симметрично. Медиана устойчивее среднего к выбросам и дорогим/редким наблюдениям.

Для остальных числовых признаков также используется медиана. Это единая устойчивая стратегия, не зависящая от экстремальных значений. Все медианы вычисляются только во время `fit` на train.

После заполнения пропусков числовые признаки стандартизируются через `StandardScaler`: из каждого значения вычитается среднее train и выполняется деление на стандартное отклонение train.

### Категориальные признаки

Для `Embarked` и `CabinDeck` используется отдельная категория `Unknown`, а не число `0`. Это важно: отсутствие порта или номера каюты не означает отдельное числовое значение и не должно создавать ложный порядок между категориями.

Для категориальных столбцов применяется `OneHotEncoder`. Параметр `handle_unknown="ignore"` позволяет обработать категорию, которая встретилась в test, но не встретилась в train, без ошибки и без изменения размерности матрицы.

## Как исключается утечка

1. Сначала выполняется `train_test_split` с `stratify=y`.
2. Затем `pipeline.fit_transform(X_train, y_train)` вычисляет медианы, средние, стандартные отклонения и список one-hot категорий только по train.
3. Для тестовой выборки вызывается только `pipeline.transform(X_test)`.
4. Test не участвует в обучении imputer, scaler или encoder.
5. В конце сравниваются размерности преобразованных `X_train` и `X_test`.

## Запуск

Из корневой папки проекта:

```powershell
python -m pip install pandas scikit-learn
python CW3\pipeline.py
```

Или через Python Launcher:

```powershell
py -m pip install pandas scikit-learn
py CW3\pipeline.py
```

Ожидаемая проверка в выводе:

```text
Размерности совпадают: True
Пропуски после преобразования: train=0, test=0
```
